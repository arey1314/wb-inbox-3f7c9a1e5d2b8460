> 本文件回答"双轨方案"能否成立的法律边界：**用禁商用数据"研究"产出的技法，能不能进商用产品？**

## 〇、一句话结论（准话）

**选 A★ ——"可迁移"为版权法一般原则，但对"合同/许可限制型源"做硬排除（该类归入 C）。**

- **版权法上**：技法 = 方法/规律/系统，**不保护表达只保护思想**（US Copyright Act §102；中国《著作权法》思想/表达二分）→ 从数据中抽象出的"回应技法"本身**不可版权化**，原则可迁移。
- **但**：迁移能否商用，**不取决于版权，取决于数据源的许可/合同条款**：
  - **JDDC**（学术协议"商业产品不得直接或间接使用"）= 合同条款，约束"派生/间接使用" → **C 硬禁**（除非京东书面商业授权，已裁决不启动）。
  - **CallCenterEN（CC BY-NC）** = NC 条件对"演绎/改编"同样生效（CC 官方：remix/transform/create-from 必须非商业）→ 商用派生**违反 NC** → **C 硬禁**。
  - **合成源（Kapibala / SalesLLM-10k / CCSE-CS）** = 非真实语料、无版权人，但本就红线禁入语料；其**框架/方法论可 A**（已裁决"作方法论参考"）。
- ⇒ 商用轨的技法**应优先源自**：① 自有 L0 锚点（客户 KB/公开规则/付费 DataTang）② 全网公开、可商用或公共领域事实 ③ 从合成/受限源**仅借鉴的"分类维度/标签体系"（去语料化）**。凡分析原点回溯到 JDDC/CC BY-NC 的技法条目，**不得进商用轨**。

## 一、A/B/C 选择 + 依据（唯一最急）

| 选项 | 含义 | 裁定 |
|---|---|---|
| **A 可迁移** | 结构/洞察/分岔类型可用，语料不用 | ✅ **一般原则**（仅限"方法/思想"层） |
| **B 需改造** | 去标识化/不保留原文/统计聚合 | ⚠️ **作为 A 的执行门槛**（见 §二执行标准），非独立选项 |
| **C 完全不可** | 研究只验证方法论 | 🔴 **对合同/许可限制型源（JDDC、CC BY-NC）强制适用** |

### 依据链（三层）

1. **版权层（支持 A）**：技法属"方法/系统/事实"，版权不保护（已核验：US Copyright Office Circular 1/31；中国《著作权法》）。即便对方数据有版权，也不及于你从中归纳的抽象技法。
2. **许可层（限制 A）**：CC BY-NC 的 NC 对"改编/演绎"同样约束 → CallCenterEN 的派生商用违规；CC BY 4.0（Kapibala/SalesLLM 表面许可宽松）则商用无碍，但二者是合成数据，触发另一条红线（L3 禁语料）。
3. **合同层（最强限制）**：JDDC 学术协议明文"any commercial product cannot use the dataset directly or indirectly" → 合同义务超越版权，派生洞察亦在"间接使用"射程内 → **C**。

**→ 定调：A★（版权允许迁移）+ 源分级硬排除（JDDC/CC BY-NC = C；合成源 = 框架 A / 语料 C）。**

## 二、执行标准：怎么算"改造够了"（A★ 落地门槛）

若某技法源自可商用源（或仅借鉴受限源的"维度框架"），须满足以下 **5 条全过**方准入商用轨：

| # | 标准 | 验证方式 |
|---|---|---|
| S1 | **抽象层级达标**：商用条目只存"规则/标签/参数/分岔树"，**零**对话原文 | 人工审查 + 关键词/长串匹配扫描 |
| S2 | **清洁室派生**：撰写人未直接复制研究轨语料；基于"公开分类维度"独立成文 | 撰写人声明 + 溯源记录 |
| S3 | **无近接**：商用条目任意连续 ≥12 词 不得命中任何研究轨语料 | 自动化相似度闸门（余弦/子串） |
| S4 | **溯源可证**：每条商用技法标注 `derivation=clean_room｜schema_only｜human_authored`，**不得**出现"提取自 JDDC 第 X 行" | 元数据必填校验（缺省拒） |
| S5 | **法务闸门**：凡分析原点含 JDDC/CC BY-NC 的条目，**强制法务签字**方可发布 | 发布前合规签字 |

> ⚠️ S4 是关键：商用轨条目的 `source` 字段只能指向 **L0 合规锚点**（客户 KB / 公开规则 / DataTang / 已确认可商用源 / "公开方法论维度"），**不得指向研究轨受限数据集**。

## 三、研究轨红线（P0）

研究轨"不受商用许可限制"成立，但**不是无限制**。红线如下：

1. **目的限制**：仅用于分析/方法论验证/标签体系设计；**不得**用于训练商用产品模型、不得产出可直用商用语料。
2. **来源合规（研究侧）**：
   - JDDC：须先注册并签署学术协议（非"自由使用"），仅限学术研究，不得外传语料。
   - CallCenterEN（CC BY-NC）：研究（非商业）可用，须**署名 + 保留声明**，不得再分发商用。
   - 合成源（Kapibala/SalesLLM/CCSE-CS）：研究可用（无真实个人），但**不得作语料入库**（L3 红线），仅框架参考。
   - 淘宝ECD/议价：真实但 `unconfirmed`，研究侧也先查授权再下，不先下后补。
3. **留痕**：每个研究洞察记录 `source + license_status=research_only + 用途`；不得脱去来源标注。
4. **不分发**：研究轨语料/中间产物**不得对外提供、不得进商用仓库、不得进生产流水线**。
5. **不反向流**：研究轨文本**严禁粘贴**进商用仓库（见 §四隔离标准）。
6. **留存与销毁**：研究产物存隔离环境，定期 purge；商用发布后研究侧副本标注"已派生，源语料不下放"。

## 四、双轨隔离标准（P0）

### 4.1 是否需要物理隔离？**是，强制。**

| 维度 | 研究轨 | 商用轨 |
|---|---|---|
| 代码仓库 | 独立 repo（`emotion-taohu-research`） | 生产 repo |
| 数据库 | 独立 DB（`research_corpus` / `research_insights`） | 生产 `kb_industry.db` / 技法库 |
| 运行环境 | 隔离沙箱，无生产 pipeline 访问 | 生产环境 |
| 人员/权限 | 研究员；**无生产写权限** | 产研；**无研究语料读权限** |

### 4.2 商用轨入库时怎么证明"这条没带研究轨语料"？

**三道闸门（缺一道即拒）**：

1. **独立可派生性**：商用条目必须能证明"仅依据公开方法论维度 + 自有/合规锚点"独立成文。撰写人提交 `derivation` 说明。
2. **相似度闸门**：入库前对研究轨全量语料跑相似度扫描，商用条目命中即拒（S3）。
3. **合规审计签字**：合规（E4）+ 法务对 `source` 字段与溯源记录签字，确认无受限源回溯。

> 物理隔离 + 条目级 `origin_track`（research/commercial）+ `license_status` + 相似度闸门 + 签字，构成完整证据链。"证明没带"= 证明它**只能从合规源派生**。
