## 一、🔴 CCSE-CS 许可结论（最急 · P0）

**一句话：语料禁入（合成数据，触发红线）；框架可作方法论参考（与裁决①同口径）。C0 说的"价值最高"成立，但价值在框架不在语料。**

### 1.1 事实核验（原文）
- **出处**：北航 CCSE（计算机学院），论文 *Culturally-Aware Empathetic Dialogue for Chinese Customer Service*，**EMNLP 2026**；仓库 `github.com/haimianxing/CCSE-CS-Empathetic-Culture-AI`。
- **规模/结构**：9,478 对话 / 约 77,000 轮；四维框架 = 关系导向 / 面子保全 / 委婉度 / 冲突强度；**18 种中文共情子策略**（敬语、集体框架、间接纠正等）；覆盖电商/银行/电信/医疗四行业。
- **🔴 关键发现——数据是 LLM 合成的，不是真实人类对话**：官方仓库 README 的"How to Run It"明写：
  ```
  export DASHSCOPE_API_KEY="your-api-key"   # 阿里云百炼 LLM 网关
  python scripts/generate_dialogues.py --num-dialogues 100 --domains all
  ```
  即对话由 LLM（通义千问/OpenAI）经 prompt 生成，与 Kapibala/SalesLLM 同一类**纯 AI 合成**，非真实客服实录。

### 1.2 许可状态（诚实标注）
- 仓库标 "open-source"，但**公开页面未明示 LICENSE 具体条款**（未读到 LICENSE 文件原文）。
- ⚠️ **许可问题在此已次要**：无论其是 CC BY 还是 Apache，合成数据本质已触发红线（裁决① + §四 红线条款）。
- **待 E3 从仓库 LICENSE 文件确认**：即便将来引用其框架，方法论参考也应保留作者署名（学术规范），不侵害其著作权。

### 1.3 入库裁定（E4 建议）
| 用途 | 裁定 | 依据 |
|---|---|---|
| **作语料入库**（训练/蒸馏技法库） | 🔴 **禁止** | 合成数据，与 Kapibala/SalesLLM 同性质，红线 L3 覆盖；且合成做训练信号会污染技法库真实性（"刚栽过跟头"） |
| **作方法论参考**（借鉴 18 子策略 + 四维框架，设计我方标签体系） | ✅ **允许** | 与裁决①完全一致；这正是 C0 所指"中文情绪技法最高价值"——框架可引用，语料不下载 |
| **在哪拿** | GitHub 仓库（读论文 + 框架定义）／EMNLP 2026 论文 | 框架为论文文本，不构成数据集授权问题 |

**预警**：若有人把 CCSE-CS 当"高价值真实中文共情语料"下载入库 = 同时踩两条雷（合成红线 + 许可未核）。本件已把它与 Kapibala/SalesLLM 一并列入 `SYNTHETIC_SOURCES` 黑名单（语料口径）。

## 二、L0 锚点定义改版（不再依赖"大量真实对话"）

**旧 L0 定义（已废）**：以"规模化真实对话语料"为唯一可信锚——JDDC/淘宝ECD 为主力，合成禁。
**新 L0 定义（生效）**：真实对话语料规模化已不可行（JDDC 禁、合成禁、其余待核），L0 改为**四类合规锚点**，`real dialogue corpus` 不再是前提。

### 2.1 四类锚点分级（红线内）

| 锚点 | 来源属性 | 合规风险 | 入库前置（必须） | 红线条 |
|---|---|---|---|---|
| **L0-A 客户知识库/SOP**（穿云豹 100 条 FAQ 这类） | 客户自有 / 我方沉淀，授权明确 | 🟢 最低 | ① 客户授权书（允许商用沉淀）② PII 脱敏抽验 | GREEN 绿通 |
| **L0-B 行业规则资料**（退换货政策 / 退费规定，**非对话、是规则**） | 公开/官方文件，无个人信息、非对话 | 🟢 低 | 来源真实性核验（官方出处，非二手搬运） | GREEN 绿通 |
| **L0-C 付费数据集**（数据堂） | 商用付费，有授权书 | 🟡 中 | ① 授权书/发票归档 ② 授权范围覆盖"商业产品化" ③ PII 复脱敏 | YELLOW 黄通（授权归档后放行） |
| **L0-D 大模型行业知识**（经客户确认后升格） | **本质 = LLM 合成** | 🔴 高 | ⚠️ 默认 `synthetic_pending`/`未确认`，**禁止入库**；仅经客户**书面确认 + 升格流程**后才可，且必须标注"合成知识·非真实语料·AI 生成" | RED-PENDING 红通待确认 |

**要点**：L0-D 是唯一的"条件升格"锚点——它默认不在 L0 内，必须客户显式确认才升格。其余三类一旦满足前置即绿/黄通放行。

### 2.2 旧真实性分层（L1/L2/L3）的处置
旧 L1（真实人类对话）/ L2（真实蒸馏模拟）/ L3（纯合成）**仍作为对话类内容的横切校验保留**，但现实效果是：L3 合成=禁；L1 真实对话=待核（淘宝/议价）；L2 蒸馏=空。新 L0 四类锚点**优先于**旧分层适用——即凡落入 L0-A/B/C/D 且通过前置的来源，不再要求"真实对话"底座。

## 三、"未确认"标记机制（P0）

**原则：任何入库前 source / license / synthetic-status 不能 affirmative 归类 → 一律打 `UNCONFIRMED` 并隔离，不得入库。**

### 3.1 标记字段设计（建议 E3 元数据 schema）
```
license_status ∈ {
  owned,            # L0-A 客户授权
  public,           # L0-B 公开规则
  licensed,         # L0-C 付费授权（需 license_file 路径）
  synthetic_pending,# L0-D 合成，未升格
  unconfirmed       # 任何无法归类
}
```

### 3.2 阻断规则
- `license_status == unconfirmed` 或 `None` → **BLOCK**（隔离待核，E3 去查许可后方可重判）
- `license_status == synthetic_pending` → **BLOCK**（须客户书面确认升格流程后才解除）
- 已确认项（`owned/public/licensed`）→ 必须在 metadata 留痕：`license_file` 归档路径 + `confirmed_by` + `confirmed_at`，供审计。

### 3.3 适用场景
- 淘宝 ECD / 议价语料：当前 = `unconfirmed`（内容真实但许可未核）→ 隔离，E3 查到授权书后改为 `licensed`/`owned` 再入库。
- 任何新来源首次入库前未填 `license_status` → 系统默认 `unconfirmed`，拒绝。

## 四、🔴 红线最终文本（可直接写进 E3 代码断言）

### 4.1 文本条款（固化）
> **红线 R-DATA-01（合成数据禁入）**：禁止任何纯 AI 合成对话/知识语料作为语料入库（含 LLM 角色扮演生成、prompt 模拟生成、经 LLM 网关批量生成）。Kapibala / SalesLLM-10k / CCSE-CS / QingshanAI 及同类一律禁止入库。若仅作方法论参考（借鉴标签体系/框架），须走独立参考通道、**不入库、不蒸馏、不进技法库**，并保留原作者署名。
>
> **红线 R-DATA-02（商用禁止数据集碰触即拒）**：CallCenterEN（CC BY-NC 4.0）、JDDC（学术使用协议，商用禁止）列入永久黑名单，任何下载/入库动作禁止。
>
> **红线 R-DATA-03（许可未确认隔离）**：任何来源 `license_status` 为 `unconfirmed` / `synthetic_pending` / `None` 的，强制隔离，不得入库；须确认并归档授权文件后重判。
>
> **红线 R-DATA-04（仅 L0 锚点可入）**：仅 L0-A（客户授权知识库）/ L0-B（公开行业规则）/ L0-C（付费授权数据集，授权归档后）/ L0-D（合成知识，客户书面升格后且标"合成"）四类锚点来源可入；其余一律拒。

### 4.2 代码断言（E3 可直接适配）
```python
# ===== E4 数据集入库红线断言（前置校验） =====
SYNTHETIC_SOURCES = {            # R-DATA-01 语料黑名单（合成）
    "kapibala", "salesllm-10k", "ccse-cs",
    "qingshanai",                # 及任何 LLM-roleplay / prompt-sim 合成
}
BANNED_COMMERCIAL = {            # R-DATA-02 商用禁止黑名单
    "callcenteren",              # CC BY-NC 4.0
    "jddc",                      # 学术协议，商用禁止
}
L0_ANCHORS = {                   # R-DATA-04 仅四类锚点可入
    "owned",          # L0-A 客户授权知识库
    "public",         # L0-B 公开行业规则
    "licensed",       # L0-C 付费授权（需 license_file）
    "synthetic_confirmed",  # L0-D 客户书面升格后
}
BLOCK_STATUSES = {"unconfirmed", "synthetic_pending", None}  # R-DATA-03

def check_dataset_admission(meta) -> ("PASS"|"REJECT", str):
    # R-DATA-01：合成语料禁入
    if meta.source in SYNTHETIC_SOURCES:
        return "REJECT", "纯AI合成语料禁入L0/技法库；可作方法论参考，不入库"
    # R-DATA-02：商用禁止黑名单
    if meta.source in BANNED_COMMERCIAL:
        return "REJECT", "商用禁止数据集，触碰即法务风险"
    # R-DATA-03：许可未确认隔离
    if meta.license_status in BLOCK_STATUSES:
        return "REJECT", f"许可状态={meta.license_status}，隔离待核，不得入库"
    # R-DATA-04：仅 L0 锚点
    if meta.anchor_type not in L0_ANCHORS:
        return "REJECT", "非L0锚点来源，不得入库"
    # L0-C 付费：必须已归档授权文件
    if meta.anchor_type == "licensed" and not meta.license_file:
        return "REJECT", "付费数据集须归档授权书/发票后放行"
    # 通过
    return "PASS", f"L0-{meta.anchor_type} 放行（已留痕 {meta.confirmed_by}@{meta.confirmed_at}）"
```

> 注：`meta.source` 用来源标识（小写），`meta.anchor_type` 用 L0 锚点键，`meta.license_status` 用 §三 枚举。E3 落库时**每个数据集必须带这三字段**，缺字段默认 `unconfirmed` → 拒。
